## 0. 들어가면서

비즈니스에 따라 기본 키(PK, Primary Key) 값을 애플리케이션에서 직접 지정하지 않고, 자동으로 생성된 키 값을 사용하는 경우가 있다. `JPA`는 기본 키 자동 발급 기능과 몇 가지 전략을 제공한다. 이번 글에서는 전략별로 어떤 차이가 있는지 정리했다.

## 1. GenerationType.IDENTITY 전략

> 기본 키 생성을 데이터베이스에 위임한다.

### 1.1. 테이블 생성

기본 키 생성을 데이터베이스에 위임하기 때문에 테이블을 생성하는 DDL(data definition language) 쿼리에 자동 키 발급 내용이 필요하다. 이 내용은 데이터베이스 벤더에 따라 다르게 작성한다. H2 데이터베이스는 다음처럼 `generated by default as identity` 키워드를 추가해 기본 키를 자동으로 발급한다.

```sql
create table identity_entity (
    id bigint generated by default as identity,
    primary key (id)
)
```

### 1.2. JPA 지연 쓰기 불가

`IDENTITY` 전략은 영속성 컨텍스트(persistence context)의 장점 중 하나인 `지연 쓰기`가 불가능하다. `IDENTITY` 전략을 사용하면 기본 키 값은 실제 데이터베이스에 데이터를 저장한 이후에 확인할 수 있다. 영속성 컨텍스트는 엔티티(entity)를 1차 캐시에 저장하려면 기본 키 필드(`@Id` 애너테이션이 붙은 필드)에 값이 필요하기 때문에 `save` 메서드를 수행할 때마다 `insert` 쿼리를 `flush`한다.

### 1.3. IDENTITY 전략 동작 확인

IdentityEntity 클래스는 `@GeneratedValue` 애너테이션의 생성 전략을 `GenerationType.IDENTITY`로 지정한다.

```java
package blog.in.action.identity;

import lombok.Getter;

import javax.persistence.Entity;
import javax.persistence.GeneratedValue;
import javax.persistence.GenerationType;
import javax.persistence.Id;

@Getter
@Entity
public class IdentityEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
}
```

IdentityTests 클래스에서는 반복문으로 데이터를 3회 추가한 뒤, 데이터를 조회해 발급된 기본 키 값을 확인한다.


## 2. GenerationType.SEQUENCE 전략

> 데이터베이스의 시퀀스 객체(sequence object)를 이용하여 유일한 값을 순서대로 생성합니다.

### 2.1. 시퀀스 객체와 테이블 생성

`GenerationType.SEQUENCE` 전략은 데이터베이스에 미리 만들어진 시퀀스 객체를 사용한다. 시퀀스 객체를 만들고 사용하는 방법은 데이터베이스 벤더마다 다르다. H2 데이터베이스에서는 다음처럼 `my_seq`라는 이름의 시퀀스 객체를 생성한다. 최초 값은 1에서 시작하고, 사용할 때마다 1씩 증가한다.

```sql
create sequence my_seq start with 1 increment by 1
```

### 2.2. SEQUENCE 전략 동작 확인

SequenceEntity 클래스는 `@GeneratedValue` 애너테이션의 생성 전략을 `GenerationType.SEQUENCE`로, 기본 키 생성자를 `SEQ_GENERATOR`로 지정한다. `@SequenceGenerator` 애너테이션에는 다음 값을 설정한다.

- name - 기본 키 생성자 이름은 `SEQ_GENERATOR`이다.
- sequenceName - `SEQ_GENERATOR`가 사용할 데이터베이스의 시퀀스 객체는 `MY_SEQ`이다.
- allocationSize - 시퀀스 객체 호출 시 증가하는 값은 1로 지정한다.

```java
package blog.in.action.sequence;

import lombok.Getter;

import javax.persistence.*;

@Getter
@SequenceGenerator(
        name = "SEQ_GENERATOR",
        sequenceName = "MY_SEQ",
        allocationSize = 1
)
@Entity
public class SequenceEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "SEQ_GENERATOR")
    private Long id;
}
```

## 3. GenerationType.TABLE 전략

> 키 생성 전용 테이블을 하나 만들고 여기에 이름과 값으로 사용할 컬럼을 만들어 데이터베이스 시퀀스를 흉내내는 전략입니다.

### 3.1. 테이블 생성

시퀀스 값을 발급하는 테이블을 별도로 만들기 때문에 데이터베이스 벤더에 의존하지 않는다. 모든 데이터베이스 벤더에서 똑같이 사용할 수 있지만, 시퀀스 테이블 생성과 초기화 작업이 반드시 먼저 이뤄져야 한다.

H2 데이터베이스에서는 시퀀스 이름(sequence_name)과 시퀀스 값(next_val)을 가지는 테이블을 만든다. 시퀀스 이름을 따로 지정하지 않으면 기본값으로 엔티티 이름을 사용한다. 테이블을 만든 뒤에 사용할 시퀀스 이름과 초기 값을 `insert`한다.

```sql
create table seq_table (
   sequence_name varchar(255) not null,
    next_val bigint,
    primary key (sequence_name)
)

insert into seq_table(sequence_name, next_val) values ('table_entity', 0)
```

### 3.2. TABLE 전략 동작 확인

TableEntity 클래스는 `@GeneratedValue` 애너테이션의 생성 전략을 `GenerationType.TABLE`로, 기본 키 생성자를 `TABLE_SEQ_GENERATOR`로 지정한다. `@TableGenerator` 애너테이션에는 다음 값을 설정한다.

- name - 기본 키 생성자 이름은 `TABLE_SEQ_GENERATOR`이다.
- table - `TABLE_SEQ_GENERATOR`가 사용할 데이터베이스의 테이블은 `SEQ_TABLE`이다.
- allocationSize - 시퀀스 테이블 사용 시 증가하는 값은 1로 지정한다.

```java
package blog.in.action.table;

import lombok.Getter;

import javax.persistence.*;

@Getter
@TableGenerator(
        name = "TABLE_SEQ_GENERATOR",
        table = "SEQ_TABLE",
        allocationSize = 1
)
@Entity
public class TableEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.TABLE, generator = "TABLE_SEQ_GENERATOR")
    private Long id;
}
```

TableTests 클래스도 마찬가지로 반복문으로 데이터를 3회 추가한 뒤, 데이터를 조회해 발급된 기본 키 값을 확인한다.


테스트 수행 로그로 동작 과정을 살펴보자. `JpaRepository`의 `save` 메서드를 수행할 때마다 시퀀스 값을 발급받는데, 이를 위해 다음 두 쿼리가 수행된다.

- `select` 쿼리 - `seq_table` 테이블에서 엔티티에 해당하는 시퀀스 값을 조회한다. `for update` 키워드로 시퀀스 데이터를 조회하면서 락(lock)을 건다.
- `update` 쿼리 - `seq_table` 테이블에 해당 엔티티가 다음에 사용할 시퀀스 값을 `update`한다.

## 4. GenerationType.AUTO 전략

> 데이터베이스에 따라 INDENTITY, SEQUENCE, TABLE 전략 중 하나를 자동으로 선택한다.

키 생성 전략이 정해지지 않은 개발 초기 단계나 프로토타입을 개발할 때 편리하게 사용할 수 있다. 데이터베이스 벤더마다 다른 전략을 선택하기 때문에 `SEQUENCE`, `TABLE` 전략이 선택되면 선행 작업이 필요할 수 있다. 예를 들어 H2 데이터베이스는 `SEQUENCE` 전략을 사용하므로 AUTO 전략을 사용할 때 다음처럼 시퀀스 객체를 생성한다.

```sql
create sequence hibernate_sequence start with 1 increment by 1
```
