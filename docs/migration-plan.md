# 기존 글 마이그레이션 계획

> Jekyll에서 Astro로 옮길 때 세운 계획을 기록으로 남긴 문서입니다. 전환을 마치면서 변환 도구(`scripts/migrate-content.mjs`)와 Jekyll 원본(`_posts` 등)은 삭제했으므로, 문서 속 명령과 경로는 git 이력에서 확인해야 합니다. 현재 글 작성 방법은 [README](../README.md)를 따릅니다.

## 범위

- 기술 글 525편을 새 Astro Markdown 형식으로 변환한다. 확장자가 없는 `_posts/2100-01-01-post-format-md`는 글이 아닌 작성 템플릿으로 분류한다.
- 회고 16편은 Logs에서 별도로 유지한다. 현재 시안의 Logs 목록은 기존 운영 글로 연결되며, 전환 시 회고 상세 페이지도 기존 주소에 생성한다.
- 독서 기록 10편은 새 내비게이션, Archive, 검색에서 제외한다. 기존 공개 주소의 콘텐츠는 보존하는 방향으로 준비하고, 공개를 종료할 범위가 있다면 전환 전에 별도로 확정한다.
- About은 업데이트된 소개, 주요 성과와 원본 상세 이력을 유지한다. 집필 도서는 Home과 About에서 소개한다.
- 작업은 `feat/astro-blog-redesign`에서 진행한다. 운영 배포는 사용자 승인 이후에만 진행한다.

## 기준 자료 확보

1. 원본 커밋 SHA를 고정한다. 해당 커밋을 현재 배포와 같은 Ruby/Jekyll 설정으로 빌드하고, 운영 사이트맵·목록·RSS와 비교한다. 서로 다른 경로가 발견되면 원인과 처리 방식을 기록한다.
2. 원본 파일과 공개 경로를 연결하는 목록을 만든다. 글 종류, 원본 파일 SHA-256, 공개 경로, canonical, 게시일·수정일, 카테고리 순서, 본문 앵커, 이미지, 링크, 댓글 이슈 번호를 기록한다. `/posts/`, `/categories/`, `/logs/`, `/books/`, 기존 페이지 번호 주소도 조사한다.
3. `/:categories/:title/`과 `/:categories/:path/`는 기존 구조를 이해하는 데 사용한다. Astro는 Jekyll 출력과 운영 주소에서 확인한 경로를 명시적으로 받아 정적 경로를 만든다. 대소문자, 인코딩, 카테고리 순서와 끝 슬래시를 그대로 비교한다.

현재 감사는 저장소 파일과 운영 페이지 표본을 기준으로 했다. 운영 URL 전체와 Jekyll 산출물의 대조를 마친 뒤 변환을 시작한다.

## 새 글 포맷

Astro 콘텐츠 컬렉션은 다음 필드를 검증한다. 기존 글의 URL은 작성자가 카테고리를 수정해도 유지된다.

```markdown
---
title: "코틀린 코루틴 아키텍처 (Kotlin Coroutine Architecture)"
publishedAt: "2026-10-31"
updatedAt: "2026-10-31T23:30:18+09:00"
canonicalPath: "/kotlin/coroutine/asynchronous/architecture/kotlin-coroutine-architecture/"
categories:
  - kotlin
  - coroutine
  - asynchronous
  - architecture
---

## 0. 들어가면서

원본 본문을 변환 규칙에 따라 유지한다.
```

| 필드 | 변환 기준 |
| --- | --- |
| `title` | 원본 제목을 유지한다. |
| `publishedAt` | 기존 공개 게시일을 ISO 날짜 문자열로 저장한다. 파일명의 날짜와 Jekyll 출력이 다르면 원인을 먼저 확인한다. |
| `updatedAt` | 기존 수정일을 보존한다. 시간대 표기가 없는 글은 Jekyll 출력의 유효 시간대를 기준으로 정규화한다. |
| `canonicalPath` | 확인된 기존 공개 경로를 저장한다. 중복 경로는 빌드 오류로 처리한다. |
| `categories` | 원본 `category` 값을 순서대로 복사한다. 대표 분류와 필터 규칙은 아래에 정리한다. |
| `tags`, `summary` | 선택 필드다. 원본에 없는 태그나 요약은 비워 둔다. |
| `recommendedPosts` | 원본의 읽기 전·후 추천 링크를 제목과 주소 목록으로 합쳐 저장한다. |

코드, 표, 인용, 링크 정의와 일반 이미지는 표준 Markdown으로 작성한다. 기존 `search: false`는 Jekyll 설정으로 기록하고, 새 검색에는 공개 기술 글을 포함하는 별도 정책을 적용한다.

### 대표 분류와 코드 언어

- Home과 Archive 목록의 대표 키워드는 `categories[0]`에서 가져온다. 예를 들어 코루틴 글은 원본의 첫 분류인 `kotlin`을 표시한다. 첫 항목이 `information`이면 그대로 표시한다. 본문에서 언어나 기술을 추측해 대표 분류를 바꾸지 않는다.
- 글 상세, Archive 필터, 검색에는 원본 카테고리 전체를 사용한다. 대표 표시와 별개로 명시된 태그도 검색에 포함한다.
- 코드 하이라이트 언어는 각 Markdown 코드 블록의 언어 표기에서 읽는다. 글의 대표 분류나 본문으로 추정하지 않는다. 언어가 비어 있거나 지원하지 않는 표기는 일반 텍스트로 표시하고, 지원하지 않는 표기는 변환 보고서에 남긴다.

### 읽기 전·후 추천 글 병합

1. 원본의 `RECOMMEND POSTS BEFORE THIS`와 `RECOMMEND NEXT POSTS`를 Markdown 제목 기준으로 찾는다. 기술 글 525편에서 각각 269편, 126편에 있으며 두 섹션이 함께 있는 글은 60편이다. 링크가 본문에 직접 적혀 있든 참조 정의를 가리키든 원래 제목과 주소를 보존한다.
2. 읽기 전 추천 → 읽기 후 추천 순으로 합치고, 각 섹션 안의 순서를 유지한다. 같은 목적지는 첫 항목만 남긴다. 내부 글의 주소 별칭은 기준 경로 목록으로 대조하고, 링크의 쿼리나 앵커가 다르면 각각 유지한다.
3. 변환된 링크는 글 하단의 **함께 읽으면 좋은 글**에 한 번만 표시한다. 작성자가 고른 링크를 먼저 보여주고, 중복을 제외한 자동 추천을 그 뒤에 둔다. 기존 추천 섹션 앵커는 새 목록에 연결되도록 보존한다.
4. 제목이나 주소를 확정할 수 없거나 예상과 다른 구문이면 해당 섹션을 원문에 남기고 보고서에 기록한다. 추천 목록 밖에서도 쓰이는 링크 정의는 유지한다.

### About 구성

- 소개 첫 줄에 현재 직함인 **비카인드랩스 시니어 소프트웨어 엔지니어**를 표시한다. 기존의 별도 **현재** 섹션은 소개에 통합한다.
- 직함에는 공통 섹션 제목 크기인 20px을 적용한다. 그 아래 경력 개요, 일하는 방식, 글을 쓰는 이유는 세 문단으로 나누고 모두 14px로 표시한다.
- 소개 다음에 **주요 성과**를 고객사·기간별로 표시한다. 이어 기술 스택, 집필, 경력과 학력을 원본 순서대로 유지한다. 회사별 하이라이트는 접힌 상태에서도 보이고, 상세 프로젝트와 학력은 같은 페이지에서 펼칠 수 있게 한다.
- About의 텍스트와 링크는 업데이트된 `_pages/about.md`를 기준으로 비교한다. 소개 구조를 바꾼 뒤에도 성과와 프로젝트 내용이 빠지거나 중복되지 않는지 확인한다.

## 변환 순서

1. **변환 도구 작성.** 읽기 전용 원본에서 새 콘텐츠 디렉터리로 출력한다. 같은 원본 커밋과 규칙으로 반복 실행했을 때 동일한 결과가 나오도록 하고, 미지원 구문과 변환 차이는 원본 경로와 줄 번호를 포함해 보고한다.
2. **표본 검증.** 현재 시안의 4편과 함께 외부 SVG·GIF, 로컬 이미지, 참조형 링크, 한글 소제목, 원시 HTML, CodePen, 언어 표기가 없는 코드와 드문 언어 표기를 가진 글을 검증한다.
3. **구문 변환.** Markdown 구조를 기준으로 Liquid 이미지 변수와 CodePen 포함 구문을 처리한다. 코드 블록과 인라인 코드의 리터럴은 건드리지 않는다. 외부 이미지 주소와 로컬 이미지 경로를 보존하고, CodePen은 삽입과 원본 링크를 함께 제공한다. 호환이 필요한 HTML은 허용 범위를 정한 뒤 처리한다.
4. **전체 변환.** 검증된 규칙으로 글과 회고를 변환한다. 운영 보존 대상 독서 기록은 별도 컬렉션으로 다룬다. 변환 후 새 글은 새 형식만 사용하고, 이전 원본은 비교와 롤백 기준으로 보관한다.
5. **기능 연결.** Archive는 최신 연도를 기본으로 열고, 결과가 20편을 넘으면 최신순으로 나눈다. 필터와 페이지를 URL에 기록한다. Pagefind에는 제목·본문·카테고리·명시된 태그를 포함한다. About, Logs, 추천 링크, RSS, 사이트맵을 같은 경로 목록에서 검증한다.

## 전환 기준

| 검증 | 통과 조건 |
| --- | --- |
| URL·SEO | 기존 공개 URL 누락과 경로 충돌이 각각 0건이다. 기존 앵커를 대조하고 필요한 경우 동일 주소에 호환 앵커를 둔다. canonical, Open Graph, RSS 링크와 GUID, 사이트맵, 인증 파일을 비교한다. |
| 콘텐츠 | 마이그레이션 입력으로 고정한 기술 글·회고·독서 기록 원본의 변경이 0건이다. 변환 전후의 제목·본문·표·링크와 코드 블록 개수 및 텍스트를 비교한다. 추천 링크의 병합 순서와 누락·중복 여부, 대표 분류와 전체 카테고리도 대조한다. 승인된 변환 외 차이는 모두 검토한다. |
| 이미지·삽입 | 모든 이미지와 삽입 콘텐츠의 주소를 대조한다. 기존 접근 실패와 전환으로 생긴 실패를 구분하고, 새로 깨진 참조를 해소한다. |
| 댓글 | utterances 저장소 `Junhyunny/junhyunny.github.io`와 `issue-term=pathname`을 유지한다. 기존 댓글이 있는 표본이 동일 GitHub 이슈를 불러오는지 확인한다. |
| 화면·검색 | 데스크톱과 모바일에서 메뉴, 키보드 탐색, 코드 복사, 목차, Archive 필터와 페이지 이동을 확인한다. 한국어·영어 및 혼합 질의로 검색을 검증한다. |

PR에서는 Astro 빌드와 비교 보고서를 검토한다. 운영 전환 승인이 나면 GitHub Pages 배포를 Astro 산출물로 교체하고 주요 경로와 댓글을 다시 확인한다. 전환 실패 시 직전 Jekyll 커밋과 배포 설정으로 복구한다.
